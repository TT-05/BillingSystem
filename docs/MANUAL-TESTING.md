# 手动验收清单

请用两个浏览器/隐身窗口、两个不同邮箱测试。在真实 Firebase 上还需检查邮件和授权域。

- [ ] 注册两人，验证邮件、退出/登录、刷新保持登录；密码重置链接可完成改密。
- [ ] A 创建 CAD 账本；另建 USD/CNY 账本，切换时交易互不混入。
- [ ] A 邀请 B：错误邮箱不能读/接受，未验证邮箱不能接受；正确邮箱接受成功；旧链接重复使用失败；撤销后失败。
- [ ] A 录入 90 元、A/B/C 等额（有第三人时），各 30；B 浏览器不刷新就看到记录与余额。
- [ ] 两人情况下 A 付 100、仅 B 参加，A +100 / B -100；付款人不要求参与分摊。
- [ ] 精确份额 60/40；百分比 33.33/33.33/33.34 或两人 60/40；检查总份额精确等于总额。
- [ ] 输入 0、负数、三位小数、超限金额、百分比不合计 100、精确份额不合计总额，保存失败且无历史垃圾记录。
- [ ] A/B 同时打开同一笔编辑：先保存者成功，后保存者得到版本冲突而非静默覆盖。
- [ ] 编辑金额/参与人，所有人余额实时更新，历史显示准确前后值和 actor。
- [ ] 删除支出后余额扣除；从 Deleted transactions 恢复；从历史恢复旧版本；各动作生成新审计。
- [ ] A 借给 B 100，B 部分还 30，再还 70，应全清；还款修正或软删除后余额重算。
- [ ] 结算建议不等于已付款。只有确认实际付款才改变余额；快速双击/重新点击不能重复登记同一建议。
- [ ] 支出恢复不回滚已记录的实际付款；反向余额清晰显示，必要时用新付款处理。
- [ ] 历史有服务器时间、稳定成员名字和完整值差异；正常 UI 无改写/删除历史按钮。
- [ ] B 退出后无法读账本；A 仍看到 B 的历史与余额。A 不能退出自己的账本。
- [ ] 未登录用户、第三个非成员不能访问私有记录（自动安全规则测试覆盖直接改文档 ID 的请求）。
- [ ] 断开网络后提示离线/连接中；保存不提前显示成功；重连后正确同步。
- [ ] 桌面、390px 窄屏可导航/输入/关闭对话框；键盘 Tab 与 Escape 正常。
- [ ] 真实部署后验证 Hosting URL、认证邮件、授权域、安全规则确已发布；Console Usage 低于免费额度。

## Google 登录与 bill9206 发布前检查

- [ ] .env.local 填入 Console 的 apiKey / appId，核对 authDomain / projectId，确认不会把 service-account 或 OAuth secret 放进 VITE 变量。
- [ ] 模拟器登录页点击 Continue with Google；本地身份弹窗创建账号，资料显示名字，刷新仍登录。
- [ ] 改自定义名字、创建账本，退出后用同一 Google 账号重新登录，名字与账本保留。
- [ ] 邮箱密码账号先登录，Account & profile → Link Google account；退出后两个方式都能进入原账本，UID 保持。
- [ ] 关联已属于另一 UID 的 Google 账号被拒绝，不合并或删除任何账本。
- [ ] 取消弹窗后仍可邮箱密码登录；拦截弹窗/未授权域给出明确可恢复提示。
- [ ] 资料加载失败时看到 Retry profile setup，不会误显示空账本或已同步成功。
- [ ] 发布前检查 Firebase Google provider 支持邮箱、one account per email 设置与授权域。
- [ ] 仅在所有者决定上线后部署；部署后用真实 Google 账号验证 OAuth、CSP、两种登录方式及 Firestore 规则。此真实流程未在本次任务运行。

## 成员规则修复验收

- [ ] 五名历史成员的正常非所有者可以退出，历史成员名、债务、支出和审计保留。
- [ ] 退出者不能再读账本/财务/审计；所有者不能自行退出。
- [ ] 直接 SDK 请求注入重复剩余 UID、六个重复 UID、未知 UID、其他历史 UID、空列表或非列表均被拒绝。
- [ ] 不可用退出动作删除历史成员、加入第六个历史 UID 或更改所有权。
- [ ] API key 取自当前注册 Web App 配置；不是仅检查字符串非空或生产构建成功。
